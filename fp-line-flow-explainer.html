3つの 疑問

① デフォルト 13問 も 編集 できる の？

「カスタム質問 = デフォルト + 追加」 だけど、 デフォルト の 13問 も 不要なら 消したい / 文言 変えたい。

② お客様 の LINE 情報 (userId / 名前 / アイコン) は 取れてる の？

取れてないと、 「Failed to send messages」 みたいに、 CRM から お客様 に LINE 送信 できない 問題 の 真因。

③ CRM から LINE 送信 / 返信 は できるの？

過去「送信失敗」 で 止まってた 問題、 ちゃんと 直ってる？

A

絵で わかる: ②③ は こうやって 解決済

お客様 友だち追加 → 完全自動で CRM に 全部 入る
📱
1. お客様 が 公式LINE を 友だち追加
QR コード or 友だち追加URL を スキャン / タップ。 → LINE 公式が follow イベント を Skelton サーバー に 送信。
▼
⚙️
2. Skelton webhook が 受信 + LINE API で 情報取得
userId (LINE が お客様 を 区別する ID) を 受信。
すぐ LINE Profile API を 叩いて、 名前 (displayName) と アイコン (pictureUrl) を 取得。
▼
💾
3. CRM の 顧客台帳 に 自動 で 作成
顧客カード が 自動で 1人 増える。 名前 / アイコン / userId 全部 入った 状態。 「未登録」 や 「匿名」 で 入らない。
▼
💬
4. 公式LINE から ウェルカム + アンケートURL を 自動 push
お客様 の LINE に 2通 自動で 届く:
1️⃣ 「ご登録ありがとうございます！」
2️⃣ 「📝 事前アンケート: https://… ?uid=Uxxx 付き」
▼
✏️
5. お客様 が アンケート 回答 → 同じ 顧客カード に merge
URL の uid で 「これは ステップ3 で 作った カード」 と わかる ので、 新規作成せず 既存カード に 上書き。 = 重複 ゼロ。
▼
✉️
6. CRM から 返信 / push が 100% 成功 する
送信 に 使う userId は この公式LINE の bot 自身 が 取った もの。 だから push 権限 は 必ず ある。 → 「Failed to send messages」 は 構造的に 出ない。
✓
② userId / 名前 / アイコン は 友だち追加 した瞬間 に 全部 自動で CRM に 入る。
③ 送信 / 返信 は その userId で 通る ので 構造的に 「Failed to send messages」 は 出なくなる。
B

各 FP 事業者 の 設定 (Jobs が 代行)

FP に やらせる作業 ゼロ。 全部 Jobs 側で セットアップ → 完成品 を 渡す
1
LINE Developers Console で プロバイダ 作成
「FP事業者名」 で 新規 プロバイダ 1個。 Messaging API チャネル を 1個 作成。
2
Channel access token / Channel secret を コピー
access token = 長文字列。 secret = 32文字。 stg管理画面 「公式LINE 連携」 セクション に 貼って 「接続テスト＋保存」。
3
Webhook URL を 設定
https://asia-northeast1-skeleton-fp-compass-632026.cloudfunctions.net/lineWebhook?t={tenantId} を LINE Console の Messaging API → Webhook 設定欄 に 貼る。 「Webhook の利用」 を ON。
4
あいさつメッセージ を OFF
LINE Official Account Manager の 設定。 Skelton webhook 側 で 自前送信する ので、 LINE標準の あいさつ は 切る。
5
リッチメニュー を 自動生成
管理画面 で 「リッチメニュー 再生成 (本番向け)」 ボタン を 押すだけ。 Jobs が 仕込んだ API が 自動 で 1分以内 に 配信。
6
QR / 友だち追加URL を FP に 渡す
これだけ FP に 渡せば 営業活動 で 配るだけ。 → 上の Aの 流れ が 自動で 全部 回る。
✓
LIFF / LINE Login チャネル 作成は 不要。 1テナント の セットアップ は Jobs 側 で 5分。
