CHAPTER 00 · 前提

FEMOON SaaS って 何?

サロン (美容院・エステ・整体 など) が お客様 から LINE 経由 で 予約 を 受け、 売上 を 管理 する ため の 月額課金型 クラウドサービス。 料金 は 月額 ¥9,800 (税込)、 Stripe 課金。

サロン は ふだん 「ホットペッパー」 や 「サロンボード」 で 予約 を 受けて いるけど、 LINE で 直接 予約 を 取りたい、 顧客 と LINE で やり とり したい、 という ニーズ に 応える プロダクト。 Skeleton Inc. が 開発・運営。

サロン に 提供 する 機能

  • 予約フォーム (LINE リッチメニュー から 開ける、 お客様 が 日時・コース を 選んで 予約)
  • 管理画面 (admin) (サロン側 で 予約状況・顧客情報 を 一覧 で 管理)
  • LINE 通知 (予約 入る たび に サロン と お客様 両方 の LINE に カード型 通知)
  • カレンダー追加 (お客様 が 通知 から ワンタップ で Google カレンダー に 登録)
  • 不定休 対応 (「第1火曜 休み」 等 の パターン を 予約カレンダー が 自動 認識)
SaaS とは? サロン 1件 ごと に サーバ を 立てる の ではなく、 1つ の クラウド 基盤 (Firebase) を tenant (テナント) 単位 で 切って 全サロン に 提供 する 仕組み。 サロン が 増えても インフラ 作業 は 増えない、 これ が SaaS の 強み。

CHAPTER 06 · PHASE 03

サロン が ウィザード 12問 を 入力

PHASE03
サロン 自身 が スマホ / PC で 12問 一問一答 + 不定休 設定 を 入力 する。 メアド = ログインID に なる。
サロン 8分
なぜ 大事 か
この フェーズ で 取った 情報 が そのまま サロン の 公開予約フォーム に 反映 される。 営業時間 や メニュー の typo は 後 で 修正 でき る が、 メアド だけ は 慎重 に。 入力 ミス は ログイン 不可 の 原因 第一位。
ウィザード
femoon-saas-wizard
↗ 開く

サロン が 入力 する 12項目 + α

  • Q1 店名 (例: ヘアサロン Lune)
  • Q2 業種 (美容室 / エステ / 整体 / ネイル / 他)
  • Q3 住所 (郵便番号 + 番地)
  • Q4 電話番号
  • Q5 担当者名
  • Q6 メールアドレス (= admin ログインID。 typo 厳禁)
  • Q7 開店時刻 (例: 10:00)
  • Q8 閉店時刻 (例: 20:00)
  • Q9 定休日 (曜日 複数選択 可、 例: 火曜)
  • Q10 不定休 パターン (「第N週 × 曜日」 プルダウン式、 例: 第1火曜 / 第3水曜)
  • Q11 コース メニュー (名前 + 所要分 + 料金 を 複数 追加)
  • Q12 スタッフ 名 (複数 OK、 「指名なし」 も 自動 追加 される)
不定休 の 入力 UX: 「第1火曜」 「第3水曜」 等 は プルダウン (週番号 1-5 + 曜日 7択) で 選ぶ 仕様。 サロン が フリー テキスト で 書か なくて 良い ので 表記揺れ が 出ない。
完了 判定: ウィザード Q12 を 「次へ」 で 抜けた 時点 で Firestore onboarding_requests/{id}.status='ready_for_payment' に 進む。 自動 で Stripe Checkout 画面 へ。

運用 全般 月次

月次 運用 (毎月 はじめ)

オーナー が やる こと

  • 売上 確認: Stripe Dashboard で 月初 に 全 サブスク の 課金 状況 を 確認
  • 失敗決済 対応: past_due ステータス の サブスク が あれば サロン に LINE で 再決済 依頼
  • 解約 受付: サロン から 「やめたい」 連絡 が あったら Stripe Dashboard で キャンセル + Firestore tenants/{id}.status='canceled' に 変更
  • 機能追加 要望: サロン から の 要望 を 集約 → Jobs に エスカレ

解約 フロー

サロン から 解約 希望 を 受けたら 翌月 末 で 停止 が 基本。

解約 手順

  • Stripe Dashboard > Subscriptions で 該当 サブスク を 検索
  • 「Cancel subscription」 → 「at period end」 (期間末) を 選択 (即時 では ない)
  • Firestore tenants/{tenantId}.status を 'canceled' に 変更
  • サロン admin は 月末 まで 使える (Stripe 仕様 + tenant ステータス は 月末 0時 で 自動 readonly)
  • サロン に 「○月末 で 停止 します、 ありがとうございました」 と LINE で 連絡

困った時 (FAQ)

よくある 詰まり ポイント と 対処。 解決 しない 時 は オーナー or Jobs に LINE で 「申込番号 ○○ の ここ で 詰まった」 と 投げる。

watcher の LINE通知 が 届かない
Mac mini が 起動 してる か 確認 (LaunchAgent com.skeleton.femoon-watcher)。 起動 して いれば 60秒 以内 に 新規 申込 を 拾う。 Mac mini が 落ちて いる 場合 は 復旧後 まとめて 処理 される。 申込 データ 自体 は Firestore に 残って いる ので 失われない。
サロン が ウィザード 途中 で 放棄 して いる
Firestore onboarding_requests/{id}.status が started の まま 24時間 経過 して いる 状態。 オーナー が サロン に LINE で 「URL の 続き から 再開 できます」 と リマインド。 ウィザード は localStorage 保存 なので 同じ URL を 同じ 端末 で 開けば 続き から できる。 別端末 から なら 最初 から やり直し。
サロン が 「パスワード設定 リンク 開けない」 と 言ってきた
リンク は 1回 のみ 有効 (1時間)。 期限切れ なら 再発行: Firebase Console > Authentication で 該当 ユーザー の 「︙」 → 「パスワード再設定 リンク 送信」。 または スクリプト node ~/.skeleton-femoon-watcher/regen-reset-link.mjs <email> で 再発行 可。
サロン が 「ログイン できない」 と 言ってきた
まず メアド を 確認 (申込時 と admin ログイン に 使う メアド は 同じ?)。 typo の 可能性 が 一番 高い。 次 に admin ログイン画面 の 「パスワード を お忘れ の方 は こちら」 リンク を 押して もらう → サロン の メアド に リセット メール が 自動 で 飛ぶ → メール の リンク から パス 再設定。
決済 失敗 / 「unpaid」 の まま
サロン が Stripe Checkout 画面 まで 行って カード入力 せず に 抜けた 状態 or カード エラー。 オーナー が サロン に LINE で 「決済 まだ 完了 してない みたい、 もう一度 ウィザード 末尾 から 試して」 と 連絡。 Stripe Dashboard で Payment Link を 再発行 して 直送 する 方法 も あり。 tenant は 既 に 作成 されて いる ので 同じ メアド で 再ログイン すれば そのまま 使える、 決済 だけ Stripe で 完了 すれば tenants/{id}.billing.status が active に なる。
テスト予約 入れたけど 通知 来ない
99% は LINE 4つ の 鍵 の どれか が 間違って いる。 admin 設定タブ で:
① チャネルアクセストークン は サロン に 最新 を 出し直し もらう (古い と 失効してる 可能性)
② ownerLineUid が 「U」 で 始まる 32文字 か
③ public_config/meta にも 同じ token が 入って いる か
で 確認。 サロン が 友達追加 してない LINE OA から は 送れない (404) ので、 通知先 userId の 人 が 公式 アカウント を 友達追加 してる か も 要確認。
サロン が LIFF を 自分で 作れない / 詰まった
LIFF 作成 は 一番 詰まり やすい。 詳細手順書 femoon-saas-liff-setup を 送る。 それでも 詰まったら オーナー が サロン と Zoom で 画面共有 で 一緒 に やる。 LIFF だけ は 完全代行 が 難しい (LINE アカウント の 持ち主 しか 操作できない 仕様)。
tenant を 誤作成 してしまった (削除 したい)
3点 一括 削除 が 必要 (片方 だけ 残す と ゾンビ tenant に なる):
① Firestore: tenants/{tenantId} doc + サブコレクション 全削除 (Firebase Console から 手動 or admin SDK script)
② Firebase Auth: 該当 メアド の ユーザー を Authentication 画面 で 削除
③ Stripe: 該当 サブスク を Dashboard で 即時 キャンセル + 顧客 (Customer) も 必要 に 応じて 削除
不安 なら Jobs に LINE で 「tenant {id} 削除 して」 と 投げる。
サロン から 「解約 したい」 と 言われた
Stripe Dashboard > Subscriptions で 該当 サブスク を 探して 「キャンセル」 (期間末 か 即時 か 確認)。 同時 に tenants/{tenantId}.status を 'canceled' に 変更。 サロン の admin は 月末 まで 使える (Stripe 仕様)。
サロン から 「機能 追加 して ほしい」 と 言われた
内容 を まず ヒアリング:
① admin で 対応 可能 な もの (営業時間 変更、 メニュー追加、 スタッフ追加 等) → サロン 自身 で 編集 可能 と 案内
② tenant 設定 で 対応 (休業日 一括 設定、 予約間隔 変更 等) → あなた が Firestore で 修正
③ プロダクト 改修 が 必要 な もの (新機能、 UI 変更 等) → Jobs に エスカレ。 オーナー が 優先度 判定 して 開発 ロードマップ に 入れる
「すぐ 対応 します」 と 即答 せず、 ②③ は 「持ち帰り 確認 します」 と 一旦 引き取る。
完
