0
Skeleton社 (営業)

サロン用 QR を 発行する。

商談前 に 営業担当 が サロン名 を 入れて 固有URL + QR PNG を 出力。 サロン側 は スキャンするだけ で 自分専用 の 申込フォーム に 到達できる。

Who / 誰が Skeleton社 営業担当
What / 何を サロン名 を 入力 → 固有URL と QR コード を 発行
Where / どこで QR発行ツール (femoon-saas-qr-gen)
Next / 次に QR画像 を サロン に 渡す → 商談で 説明
所要 約2分。 1サロン につき 1回 だけ 発行。 QR は 商談スライド や 印刷物 に そのまま 貼れる。
t35ty6-rgb.github.io/skeleton-demos/femoon-saas-qr-gen/
1
サロンオーナー

QR を スキャン → 申込フォーム を 開く。

サロン側 は スマホカメラ で QR を 読み取る だけ。 フォーム TOP の 上部 に 「黄色 バナー で サロン名」 が 出るので 「自分専用 の フォーム である」 と 一目 で 確認 できる。

Who / 誰が サロンオーナー
What / 何を スマホカメラ で QR スキャン → ブラウザ 起動
Where / どこで スマホ (iOS / Android、 標準カメラ アプリ)
Next / 次に フォーム TOP → そのまま 申込 ボタン に 進む
上部 の 黄色 バナー 「🏷 サロン識別子: サロン名」 が 表示 されていれば 正しい URL に 到達 できている 証拠。
femoon-saas-onboarding/?ref=...
2
サロンオーナー

Stripe で 決済 する (¥3,000 / 月)。

申込フォーム を 送信 する 直前 に Stripe Checkout が モーダル で ポップアップ。 カード番号 を 入力 して 「お支払い」 を タップ → 即時 決済成功 → そのまま フォーム送信 へ 戻る。

Who / 誰が サロンオーナー
What / 何を カード番号 / 有効期限 / CVC 入力 → お支払い
Where / どこで Stripe Checkout (PCI 準拠 ホスト)
Next / 次に 決済成功 → フォーム送信 が アンロック
⚠ 現状 Stripe バックエンド は 実装中。 本ビジュアル は 「組み込み 後 の あるべき 姿」 を 描いている。 本番化 までは テストカード 4242 4242 4242 4242 で 動作確認 可能。
checkout.stripe.com / skeleton-inc
3
サロンオーナー

申込フォーム を 1ページ で 記入 → 送信。

店名 / 業種 / 営業時間 / コース など を 上から 順 に 入力。 一番下 の 緑 「送信する」 ボタン で 完了。 別画面 への 遷移 は ゼロ、 1スクロール で 終わる 設計。

Who / 誰が サロンオーナー
What / 何を 店舗情報 / コース / スタッフ を 1ページ 記入
Where / どこで 申込フォーム (femoon-saas-onboarding)
Next / 次に 送信 → Skeleton社 側 へ 申込通知 が 飛ぶ
所要 約10分。 後から 管理画面 でも 編集 可能 なので、 とりあえず 最低限 入れて 送信 でOK。
femoon-saas-onboarding/ — 送信 直前
4
Skeleton社 (Jobs)

裏 で SaaS 設定 を 全自動 セットアップ する。

申込通知 を 受けた Skeleton 社側 が tenant 作成 → ログイン情報 発行 → 案内メール 送信 を 自動 で 一気通貫 で 実行。 サロン側 は 寝てて OK・コーヒー で 一息 つけば 完了。

Who / 誰が Skeleton社 (Jobs 自動化)
What / 何を tenant 作成 / 認証ユーザー / 予約URL 発行 / メール
Where / どこで Firestore + Cloud Functions + SendGrid
Next / 次に サロン に セットアップ完了メール が 届く
所要 約30分。 サロン側 は この間 待機 のみ。 完了 すると 自動 で 次の メール が 飛ぶ。
Skeleton Inc. — internal automation
5
サロンオーナー

セットアップ完了 メール を 受信 → ログイン。

タイトル 「FEMOON SaaS セットアップ完了」 の メール を 開く。 中に 予約URL と 管理画面 ログイン用 の パスワード が 入っている。 予約URL は コピー しておく。

Who / 誰が サロンオーナー
What / 何を 予約URL コピー + 管理画面 ログイン
Where / どこで メールアプリ → ブラウザ
Next / 次に LINE 公式アカウント 開設 (段階 6) へ
予約URL は 後の 段階 7 で LIFF の エンドポイント に 使う。 メモ帳 / Notes に 貼って おくと スムーズ。
受信トレイ — Skeleton Inc.
6
サロンオーナー

LINE 公式アカウント を 開設する (3分)。

LINE Official Account Manager で 「アカウント開設」 → アカウント名 / 業種 を 入力 → 「作成」。 既に LINE 公式 を 持っている サロン は この段階 を スキップ できる。

Who / 誰が サロンオーナー
What / 何を アカウント名 / 業種 入力 → 作成 ボタン
Where / どこで LINE Official Account Manager (manager.line.biz)
Next / 次に 公式アカウントID と Messaging API トークン を 取得
既に LINE公式 を 持っている 場合 は 段階 6 を スキップ し、 段階 7 (LIFF作成) に 直接 進む。
manager.line.biz
7
サロンオーナー

LIFF を 作成 → LIFF ID を 取得する (10分)。

LINE Developers Console で プロバイダー を 選び → 新規 LINEログイン チャネル を 作成 → 中で LIFF を 追加 → エンドポイントURL に 段階 5 で コピー した 予約URL を 貼る → 生成 された LIFF ID を 控える。

Who / 誰が サロンオーナー
What / 何を LINEログイン チャネル 作成 → LIFF 追加 → ID 取得
Where / どこで LINE Developers Console (developers.line.biz)
Next / 次に LIFF ID を Skeleton社 に LINE で 送付
注意: Messaging API チャネル に LIFF は 紐づけ できない。 必ず LINEログイン チャネル を 選ぶ。 (詳細19ステップ 指示書 参照)
developers.line.biz / LIFF
8
Skeleton社 (Jobs)

最終仕上げ: リッチメニュー差替 + E2E 動作確認 (15分)。

サロン から 受領 した LIFF ID を 元 に、 リッチメニュー画像 を 当て込み → LIFF URL を タップ領域 に 紐付け → Playwright で E2E 動作確認 → サロン に 「セットアップ完了」 を LINE で 通知。

Who / 誰が Skeleton社 (Jobs)
What / 何を リッチメニュー登録 + LIFF URL 紐付け + E2E test
Where / どこで LINE OA Manager API + Playwright
Next / 次に サロン に 完了報告 → サービス 開始
所要 約15分。 全工程 を Jobs が 自動 で 回し、 失敗 した 場合 は リトライ。 完了 時 は LINE で サロン に 通知 + 動作確認用 URL を 送付。
Skeleton Internal — Final QA
9
サロン + お客様 + システム

お客様 が LINE で 予約 → 双方 に 自動通知。

サロン が お客様 に 公式アカウント の QR を 案内 → お客様 が 友達追加 → リッチメニュー の 「ご予約」 タップ → LIFF で 予約完了 → サロン と お客様 両方 の LINE に Flex Message 通知 + 「カレンダーに追加」 ボタン。

SCENE 1 · 友達追加 → リッチメニュー
SCENE 2 · LIFF で 予約 入力
SCENE 3 · 双方 に Flex 通知
Who / 誰が サロン (案内) → お客様 (友達追加 + 予約) → システム (通知)
What / 何を QR案内 → 友達追加 → リッチメニュー → 予約 → 通知
Where / どこで LINE アプリ (お客様 スマホ) + LIFF
Next / 次に 来店 → サービス 提供 → リピート 化
Bonus / 自動化 Google Calendar 1タップ追加 + 前日 リマインド
この 段階9 が 始まる ことが 「サービス 開始」 そのもの。 ここまで 来たら 営業 として は 納品 完了。
