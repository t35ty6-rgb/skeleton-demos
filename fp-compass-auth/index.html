Implementation — 4 週間 実装ロードマップ

いつ何ができるか

各週末にオーナーと進捗レビュー。各段階で動くものが本番投入される。
W1
Week 1 — 認証基盤 構築
Firebase プロジェクト立上げ + Google ログイン実装
Firebase プロジェクト作成、Google OAuth 設定、CRM フロントエンドに認証 SDK を組込み、ログインボタン実装。今の暫定キー方式から置換。
  • Firebase プロジェクト作成 + 環境構築 (skeleton-inc.firebase.app)
  • Google OAuth プロバイダ 有効化 + ドメイン許可
  • fp-crm-prod に Firebase Auth SDK 組込
  • ログイン画面 (Google ボタン + メール代替) を新規 UI で実装
  • 認証通過後 ユーザ ID を Cloud Run プロキシに伝達
  • Week 1 末: テスト FP 1 名で動作確認
W2
Week 2 — テナント (顧客) 管理 基盤
Firestore で顧客台帳 + 顧客 ⇔ FP 紐付け
Firebase 認証ユーザを「FP テナント」と紐付けるデータベースを構築。1 ユーザ = 1 fpId、複数スタッフ対応、ロール管理 (Owner / Admin / Staff)。
  • Firestore に tenants コレクション設計 (fpId / 事務所名 / プラン / 状態)
  • Firestore に users コレクション (uid / fpId / role / 招待状況)
  • Cloud Run で Firebase ID Token 検証 + fpId 解決の middleware 実装
  • GAS との通信で fpId を強制付与 (越境防止)
  • Week 2 末: テスト FP 2 社で分離動作確認
W3
Week 3 — 管理コンソール (オーナー側)
100 社管理する Owner Console を実データ接続
既に Mock で作った Owner Console を Firestore 実データに接続。FP の追加 / 招待 / 停止 / 削除 を 1 画面で完結させる。
  • Owner Console → Firebase Admin SDK 接続
  • FP 一覧 表示 (リアルタイム同期)
  • 「FP を新規招待」ボタン (メール送付 → Magic Link)
  • 「FP を停止 / 削除」ボタン (即時無効化)
  • 「プラン変更」「MFA 必須化」設定
  • 監査ログ表示 (誰がいつログインしたか)
  • Week 3 末: 10 社規模の負荷試験
W4
Week 4 — セキュリティ強化 + 本番展開
MFA / 監査 / 障害対応 を本番運用品質に
100 社運用に耐える最終仕上げ。Pro プラン以上の MFA 必須化、不正アクセス自動検知、SLA に基づく通知体制。
  • Pro 以上の FP に MFA (Authenticator / SMS) 必須化
  • 異常ログイン (新端末 / 海外 IP) 自動メール通知
  • 監査ログ BigQuery 集約 (Phase 3 早期実装)
  • パスワード再発行 (Magic Link 自動送信)
  • 既存 Demo / Stg / Prod の URL 整理
  • Week 4 末: 本番 100 社展開 GO サイン
