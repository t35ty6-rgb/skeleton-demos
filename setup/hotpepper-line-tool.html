①客に事前依頼するもの訪問前にLINEで送る

訪問日までに客に用意してもらう。揃ってないと当日詰む。

客への文面テンプレ (コピペ用)
導入当日までに以下4点をご準備ください。 ①業務用Gmail ②LINE公式アカウント ③スタッフのLINEグループ ④サロンボードのログイン情報 当日は60〜90分ほどお時間いただきます。

②当日のオーナー作業手順順番固定

  1. 客のGoogleアカウントにアクセス(画面共有 or 一時的に預かる)
  2. LINE Developers Consoleで Messaging APIチャネル作成 → チャネルアクセストークン(長期)を発行してメモ。短期はNG(期限切れる)
  3. 通知先LINEグループIDを取得(ウィザードHTMLの手順通り: Webhook一時設定 → グループで発言 → ログからID抽出)
  4. GASプロジェクト新規作成 → Config.gs Code.gs 他を貼り付け
    ソース: hotpepper-line-tool/ の最新ファイル
  5. Config.gs に値を埋める
    • LINE_CHANNEL_ACCESS_TOKEN ← 手順2のトークン
    • LINE_TO_IDS ← 手順3のグループID
    • CALENDAR_IDS ← primary でも可
    • SALON_NAME ← 客のサロン名
    • FROM_ADDRESS は 空のまま(既知バグ回避)
  6. 予約サイト側で通知先メールを客のGmailに変更(サロンボード/楽天/minimo/EPARK)
  7. 動作確認(GASエディタで手動実行)
    • testLine → LINEグループに届く
    • testCalendar → カレンダーに入る
    • testParseLatest → 最新メール解析ログ確認
  8. installTriggers を実行 → 1分おき+月曜9時の自動化スタート
  9. 実予約 or テスト予約メール1件で end-to-end確認 → LINE届く+カレンダー入る両方

③動作確認(納品判定)

ここまで全部通ったら「導入完了」と客に宣言する。

④既知の落とし穴

FROM_ADDRESS を埋めるとマッチしなくなる — 空が正解。Configで触らない。
  • LINEトークンは 長期を発行。短期だと数時間〜数日で死ぬ
  • GASは1日のメール送信上限あり → 予約量が極端に多い客は将来対応
  • カレンダーは客のGoogleアカウント上で動く。Jobs側SAは関与しない(個人Gmail制約)
  • 客のGmailにラベル 処理済み が自動で付く → 事前に客に共有しておく
