導入パッケージの考え方

客の業務用Gmail/LINEに相乗りせず、通知ツール専用アカウントを Skeleton 側で開設して納品する。トラブル時の責任分界・解約時の安全性・代行作業の心理的ハードル、全部解決する。

P1申込時に客から取る情報

客契約書と同時に1枚で取得 / 5分
  • サロン名(屋号)
  • サロン略号(skeleton.{略号}@gmail.com に使用、半角英数3〜6文字)
  • 店舗住所
  • 代表者氏名
Gmail新規作成時の電話番号認証で必要。客の携帯番号を申込書に記載してもらう。
当日 or 事前に「Googleから6桁のコードがSMSで来るので転送してください」と1回お願いするだけ。
Phase 4 で送信先メール変更に使う。預かりではなく「画面共有しながら客が入力」運用でも可。
ホットペッパー / 楽天ビューティ / minimo / EPARK のチェック。該当のみツールで監視する。

  • 既存スタッフLINEグループあるか / 新規作成するか

P2Skeleton側の事前仕込み

Skeleton納品前日までに完了 / 60〜90分 / 客は何もしない
命名規則: skeleton.{サロン略号}@gmail.com (例: skeleton.bloom@gmail.com)
電話番号認証で客のSMSコードを1回もらう。パスワードはSkeleton側1Passwordで管理。
同一電話番号で複数Gmail作成は数アカウントまで制限あり — 必ず客の番号で認証する
LINEヤフー for Business でビジネスID登録。事業者情報(屋号・住所)はP1で取得済み。
LINE Official Account Manager で新規。
命名規則: {サロン名} 予約通知(例: BLOOM 予約通知)
Official Account Manager → 設定 → Messaging API → 「利用する」ON → LINE Developers に自動遷移 → チャネルアクセストークン(長期)発行 → 1Passwordに保存
webhook.site でURL発行 → LINE Developers の Webhook URL に貼り付け → スタッフLINEグループ作成 → 公式アカウントを招待 → グループで「テスト」発言 → webhook.siteで "groupId": "C..." 取得 → 1Passwordに保存
終わったらWebhook URLは空欄に戻す。
Skeleton管理のマスターGASプロジェクトを開く → 「ファイル → コピーを作成」 → 客のサロン名でリネーム → Config.gs に以下を埋め込む:
  • LINE_CHANNEL_ACCESS_TOKEN ← ④のトークン
  • LINE_TO_IDS ← ⑤のグループID
  • SALON_NAME ← 客のサロン名
  • FROM_ADDRESS ← 空(既知バグ回避)
  • CALENDAR_IDS ← 後でPhase 3-3で自動生成される、ここでは primary プレースホルダ
GASプロジェクト右上「共有」 → 「リンクを知っている全員(閲覧者)」 → URLコピー → 1Password 該当客レコードに保存
このURLを当日 Phase 3 で客に送る。
客に渡すA4 1枚(Google Sheets):
  • 専用Gmailアドレス / パスワード
  • LINE公式アカウント名 / 管理画面URL / ログイン情報
  • GAS共有URL(コピー用)
  • スタッフ向けLINE友達追加用 QRコード

P3当日の客作業 — ここが本番

客司が画面共有で隣に立つ / 5〜10分
P2-8の引き渡しシートのGmailアドレス + パスワードでログイン。
2段階認証設定はこのタイミングで一緒にやっておく(客の電話番号で)。
P2-7の共有URLをクリック → GASエディタ右上「コピーを作成」ボタン → 客のドライブに複製される
これで客のアカウントで動くGASプロジェクトが完成(Configは焼き込み済み)
GASエディタで関数選択 installTriggers → 「実行」
初回のみ「権限を許可」ダイアログ → 「詳細」 → 「(プロジェクト名) に移動」 → 「許可」
実行完了でトリガー2件(1分おき + 月曜9時)が設定される。
関数選択 setupSiteCalendars → 「実行」
4つのサイト別カレンダーが客のGoogleカレンダーに自動作成される(🔴ホッペ / 🌸楽天 / 🟢minimo / 🔵EPARK)
引き渡しシートのQRコードをスタッフ全員のスマホで読む。
LINE公式が既にグループに参加済み(P2-5)なので、これで通知が届く状態になる。
関数 testLine 実行 → スタッフLINEグループに「テスト通知」着弾を確認

P4サロンボード(予約サイト)送信先変更

客司が画面共有で同席 / 5分
客のログイン情報(P1-3)で サロンボード ログイン。
「店舗設定」or「メール設定」→ 通知先メールアドレスを skeleton.{略号}@gmail.com に変更 → 保存
楽天ビューティ / minimo / EPARK Beauty の管理画面でも同じ変更。

P5動作確認 → 引き渡し

Skeleton納品判定 / 10分
ホットペッパー側からテスト予約(明日以降の日時、適当な顧客名)を投入。
  • 1分以内に専用Gmailに予約通知メール着信
  • 1分以内にスタッフLINEグループに通知着弾
  • Googleカレンダーの該当サイト別カレンダーにイベント追加
  • 顧客名・日時・メニュー・担当が「⚠️取得失敗」ではなく正しく抽出されている
「通知LINE公式の見方」「もし通知止まったらSkeleton連絡」を1分で説明 → 完了。
客台帳(Sheets) に: 専用Gmail / LINE公式 / GASプロジェクトURL / 納品日 / 月次保守の有無 を記録。

!既知の落とし穴

FROM_ADDRESS を埋めるとマッチしなくなる — Config.gs では空のまま。
  • 専用Gmail作成時の電話番号認証 — 同じ番号で3〜4個までしか作れない。客ごとに必ず客の番号で認証
  • LINE長期トークンの有効期限(60日)— 期限通知の仕組みは別途検討。月次保守メニュー化候補
  • GAS共有URLを「閲覧者」で発行すること(編集権限にすると客が触ってマスターを壊すリスク)
  • 「コピーを作成」後は完全に客のアカウント所有物 → Skeleton側からはアクセスできなくなる(意図通り)
  • 2段階認証は専用Gmail作成時に必ずセット(客が後で乗っ取られないため)
